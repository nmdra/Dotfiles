Explain ${@:-the most relevant thing in the current context} clearly and completely.

Structure:

1. One-sentence summary first — what it is, why it matters.
2. How it works — mechanism, not just surface description. For code: walk the actual implementation, cite file paths, and quote the relevant lines.
3. Key details that matter in practice — edge cases, gotchas, trade-offs, common mistakes.
4. Concrete example (code or scenario) showing it in use.

Rules:

- Adapt depth to the target's complexity — no padding, no filler.
- If you are not sure what to explain or the target is ambiguous, ask one short clarifying question before answering.
- End with a "Want to go deeper?" note only if a natural next step exists.
